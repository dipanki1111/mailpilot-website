MailPilot Privacy Policy

Last Updated: October 28, 2026  |  Effective Date: October 28, 2026

This Privacy Policy explains how MailPilot handles information through our website and email productivity application.

Transparency & Architecture Commitment This Privacy Policy reflects the verified technical architecture and implementation of the MailPilot desktop application and website. We are committed to complete transparency regarding local data handling, storage boundaries, and privacy protections.

1. Scope and Introduction

This Privacy Policy applies to the MailPilot website (hosted at https://mailpilot-website.pages.dev/) and the MailPilot desktop application distributed through the Microsoft Store.

MailPilot is designed as an email productivity and search tool built on a local-first principle. We respect individual privacy and are committed to clear, truthful communication regarding our technical data practices.

2. Information Collected and How It Is Used

We differentiate between information associated with browsing our informational website and information involved when using the MailPilot desktop software.

A. Website Visitors

Our website serves purely informational purposes. You can browse our website without creating an account or providing direct personal identifiers.

  • No Tracking Scripts or Cookies: The static website source code contains no tracking scripts, advertising pixels, or analytics cookies.
  • Technical Infrastructure Logs: Like most web hosting platforms, our hosting provider (Cloudflare Pages) processes standard technical transit information (such as IP addresses, browser types, operating systems, referring URLs, and access timestamps) to deliver web pages securely and mitigate malicious traffic. Infrastructure-level network metrics may be processed by Cloudflare in accordance with their privacy practices.

B. MailPilot Application Diagnostics & Telemetry

The MailPilot desktop application is designed to operate locally on your computer:

  • No Telemetry or Analytics SDKs: The application contains no first-party or third-party telemetry frameworks, user tracking SDKs, feature analytics, or remote crash-reporting SDKs.
  • Local Diagnostic Logging: Diagnostic messages and error logs generated during email indexing are written strictly to a local text file on your machine at %LocalAppData%\MailPilot\rebuild_debug.log. These logs are stored solely on your computer and are never automatically transmitted over the network.
  • Microsoft Store Platform Telemetry: Because MailPilot is distributed through the Microsoft Store, installation delivery, update downloads, and OS-level platform crash diagnostics are managed independently by Windows under the Microsoft Privacy Statement. These platform services are not controlled by MailPilot.

3. Local Storage, Email Processing, and Outlook Connectivity

MailPilot operates on a local-first architecture. All indexing, data storage, and search evaluation happen directly on your personal computer:

A. Local Indexing and Search Execution

  • Local SQLite Database: MailPilot creates and maintains an independent search index stored in a local SQLite database file located at %LocalAppData%\MailPilot\MailPilot.db.
  • Data Stored Locally: To enable fast searching without relying on Windows Search, this database stores indexed email subjects, sender and recipient information, message dates, folder locations, flags, read statuses, preview snippets, full message body text, user preferences, and your recent search query history.
  • No Cloud Transmission of Email Data: All search queries, filter evaluations, and text matches are performed locally on your device against your local SQLite database. No email bodies, headers, recipient lists, or search query strings are transmitted to remote servers, external APIs, or cloud services.
  • Temporary Opened Attachments: When you choose to open an email attachment from the preview pane, the attachment is temporarily saved locally to %TEMP%\MailPilot\ so that your default Windows application can display it.

B. HTML Email Preview and Remote Content

When you select an email to view its full content, MailPilot displays the message body using Microsoft WebView2:

  • Local Message Rendering: The email body is passed directly from your local database or Outlook session into the local WebView2 rendering component. MailPilot does not route or proxy message content through any intermediary servers.
  • Sender-Embedded Remote Resources: If an incoming HTML email contains links to external images, web fonts, or tracking pixels embedded by the original email sender, the WebView2 component may load those external resources directly from the sender's third-party web servers over your internet connection unless blocked by your firewall or network security tools. MailPilot does not claim that no network request can ever occur during HTML preview rendering.

C. Outlook Authentication and Account Access

  • Classic Outlook COM / MAPI Connection: MailPilot connects exclusively to the local Classic Microsoft Outlook desktop client via Windows Component Object Model (COM) and the MAPI subsystem.
  • No Password or Token Storage: MailPilot relies entirely on your active, locally authenticated Classic Outlook profile. The application does not request, collect, transmit, or store email account passwords, OAuth tokens, or login credentials.
  • Desktop Client Requirement: MailPilot requires Classic Microsoft Outlook desktop and does not support the web-based New Outlook for Windows.

A. Distribution, Hosting, and Support

B. Application Libraries & Frameworks

MailPilot incorporates standard, open-source and Microsoft development libraries to provide user interface, database, and local integration capabilities:

  • Core Developer Libraries: Includes Microsoft .NET runtime libraries, Microsoft.Data.Sqlite (for local SQLite database operations), CommunityToolkit.Mvvm (for UI architecture), MaterialDesignThemes (for visual styling), and Microsoft.Web.WebView2 (for local HTML rendering).
  • No Tracking SDKs: The application contains no advertising SDKs, commercial tracking frameworks, third-party analytics packages, or behavioral monitoring tools.

5. Data Retention, Deletion, and Uninstall Lifecycle

Because MailPilot stores data locally, you maintain control over your stored information:

A. In-App History Management

  • Search History: You can clear individual previous searches or wipe your entire recent search history at any time using the Clear button in the Recent Searches panel.
  • Index Rebuilds: The in-app Rebuild Index option re-reads emails from Outlook and updates your existing database records, but it does not delete or reset the underlying database file.

B. Deleting the Local Index and Application Data

The application does not include an automated in-app "Clear Index" or "Delete Database" button. To completely delete the local search index, preferences, and diagnostic logs:

  1. Close and exit the MailPilot application completely.
  2. Open Windows File Explorer and navigate to your local application data folder:
    %LocalAppData%\MailPilot\ (typically C:\Users\<YourUsername>\AppData\Local\MailPilot\)
  3. Delete the MailPilot.db file (or delete the entire MailPilot folder).
  4. Optionally, clear temporary attachment files by deleting any files inside %TEMP%\MailPilot\.

Warning: Deleting the %LocalAppData%\MailPilot\ folder permanently removes your local MailPilot search index, saved search history, custom application preferences, and local debug logs. It will not delete, alter, or remove your original emails, folders, or mailboxes in Microsoft Outlook or on your email server.

C. What Happens When You Uninstall MailPilot

Uninstalling MailPilot via Windows Settings or the Microsoft Store removes the application executable and package assets. However, standard Windows package uninstallation does not automatically delete unvirtualized user data files located in %LocalAppData%\MailPilot\.

If you wish to remove all local traces of MailPilot from your computer upon uninstallation, please perform the manual folder deletion steps described above.

D. Support Communications Retention

If you contact us via email, we retain your message and email address only as long as necessary to answer your inquiry and maintain support history. You may request deletion of past support correspondence at any time by contacting us.

6. Security and Encryption

We prioritize data privacy through local containment and clear architectural boundaries:

  • Local Data Boundary: By indexing and processing email data locally on your computer, your messages and search terms are not routed through external application servers.
  • Database Encryption Status: The local SQLite database file (MailPilot.db) is not encrypted at the application level by MailPilot. Data at rest is protected by Windows operating system user account access controls (NTFS permissions), which restrict file access to your Windows user profile.
  • Device-Level Encryption: Additional protection at rest depends on whether device-level or volume encryption (such as Windows BitLocker or hardware device encryption) is enabled on your computer. MailPilot does not manage device-level encryption, and encryption is not enabled by default on all Windows systems.
  • Website Transport: All communication between your browser and our informational website is encrypted via modern HTTPS.
